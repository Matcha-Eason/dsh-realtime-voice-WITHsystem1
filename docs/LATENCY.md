# 延迟测量与当前结论

测试于 2026-10-26（本地时区），Apple M4 / 10 核 / 24 GB，百炼 Token Plan。固定合成中文：“我只有二十分钟，请推荐一种适合在家放松的活动。”原始音频 4.21 秒，端到端测试裁去尾部静音后为 3.95 秒。

## 结论

原版的最大单项通常是主模型首字，另有云端 ASR、重复的续说等待和过时请求排队。本地 ASR 明显缩短识别计算，但云端决策和主模型偶发慢请求仍会拖慢整轮，不能承诺每轮都在两秒内。

最终版本各测 3 轮，全部收到回答音频。相同设置下，云端 ASR 的最终识别耗时为 550–1028 ms，本地为 71–74 ms。两组端到端结果重叠：云端组主模型首字恰好更快，本地组有一轮决策耗时 885 ms。不能据此把两组总耗时差直接解释成本地模型的收益。

## 测量边界

`scripts/benchmark-voice.mjs` 使用生产轮次控制器、分句器、ASR/TTS 适配器与真实供应商接口。合成 PCM 按 20 ms 实时喂入，主模型通过流式接口接入测试用会话桥。记录的是**最后输入语音到收到首段 TTS 音频**。

它没有覆盖 DSH 的完整上下文、工具调用、真实麦克风、设备播放缓冲或房间回声；不代表真人对话的完整体感延迟。主动澄清判断开启，但测试内容要求普通回答，主动澄清的实际发声仍由行为回归测试覆盖。每组只有 3 次，不报告 P95，也不把短测成功率当作长期可用性。

原版主模型为 `deepseek-v4.1-flash`，未显式关闭供应商默认思考，尾静音 700 ms、识别后额外续说等待 400 ms。最终版主模型相同但显式 Off，尾静音 400 ms、总续说窗口 600 ms、决策总超时 4000 ms、主动澄清判断开启。两组配置同时发生多项变化，表格不是单变量实验。

尾静音读数略小于配置值，是输入音频末尾仍包含低能量采样及帧边界造成；不是配置未生效。原版第 1 轮的决策请求早于 final 启动，和等待阶段有重叠，因此各列不可直接相加。

## 独立检查

- **本地 ASR**：量化 SenseVoice，CPU 两线程，首次异步加载 461 ms；完整 4.21 秒音频连续识别五次为 83、72、72、71、71 ms，转写一致。这里不包含断句等待。原生模型为非流式识别，500 ms 滚动预览由插件实现。
- **主模型思考模式**：同一简短请求，每种配置只测一次。DeepSeek 默认思考 / Off 首正文分别为 4408 / 2048 ms，Qwen 3.8 Flash 为 2468 / 875 ms。默认模式确有推理 token，Off 没有；这验证配置有效，不是模型排行榜。
- **决策连接**：独立 HTTPS 探针的首请求 DNS / TCP / TLS 累计约 26 / 64 / 107 ms，总计 585 ms；随后五次复用连接为 105–115 ms。这次短测未复现超时，不能把其他失败一律归因于网络建立或模型计算。
- **浏览器采集**：实际浏览器以静音振荡器验证 AudioWorklet，48 kHz 输入，约 1.2 秒收到 56 个完整 20 ms 帧。没有申请麦克风。44.1/48 kHz 跨块采样连续性另由单元测试覆盖。

## 失败与修正

中间复测保留了失败，未只选最快样本：

| 配置 | 结果 |
|---|---|
| 本地、400 ms 续说窗口、4 s 决策超时 | 成功 2/3：2106、4770 ms；另一次决策超过 4 s |
| 本地、600 ms 续说窗口、4 s 决策超时、无重试 | 成功 2/3：2191、2371 ms；另一次决策超过 4 s |
| 本地、主动澄清开启、2 s 决策超时 | 成功 2/3：2491、5907 ms；另一次决策超过 2 s；慢成功轮主模型首字为 4313 ms |

云端早期复测也出现过 2 s 决策超时。输入中的逗号会被 400 ms VAD 切成两个语音段；将总续说窗口保留为 600 ms 后，两段能合并成一条提交，避免第一段刚发起判断就被第二段取消。

最终版本在总超时至少 3 s 时，允许 final 判断的首次请求超过 2 s 后重试一次，仍受总时限和用户取消控制。partial、HTTP 拒绝和无效返回不重试；失败继续显示并保留草稿。最终六轮都只发起了一次 final 请求，**没有在真实服务中触发重试**；重试成功、总超时和取消由自动测试验证，尚不能宣称它消除了供应商慢请求。

## 本次改动

1. 共用窗口调度器，final 取消过时云端预览；已完成识别时间计入续说窗口。
2. 本地 SenseVoice 使用 Host 共享的异步原生识别器；不阻塞 DSH 主事件循环。模型权重单独准备。
3. 过时决策真正取消，没有稳定文字且无回答可打断时不发起 partial 判断。
4. 显式配置主模型 Off；不更换用户选定的主模型，也不使用另一个模型生成接场话术。
5. AudioWorklet 替换主线程 ScriptProcessor，20 ms 帧；收音和播放生命周期独立。回声 partial 不再驱动语义打断，echo final 仍可解除暂停。
6. 界面提供上轮分段耗时；测量不会把推理首 token 或完整生成结束冒充首音频。

## 复测

先完成 `.env.local`、DSH 依赖链接与构建。本地识别另需 `npm run setup:asr`。

```bash
npm run check
CHECK_ASR=local npm run check:bailian
BENCH_ASR=local BENCH_LABEL=local npm run bench:voice
BENCH_LABEL=cloud npm run bench:voice
```

基准默认运行 3 轮；可设置 `BENCH_ROUNDS`、`BENCH_SILENCE_MS`、`BENCH_MERGE_MS`、`BENCH_DECISION_TIMEOUT`，或 `BENCH_PROACTIVE=false` 做对照。`BENCH_THINKING=default` 恢复供应商默认思考；`DSH_VOICE_MAIN_MODEL` 选择被测主模型。失败轮次也写入 `.local/latency-<label>.json`，不录制麦克风。该脚本会调用账户的模型服务。

当前电脑的原始报告在 `.local/latency-baseline.json`、`.local/latency-local-final.json`、`.local/latency-cloud-final.json`，诊断与合成音频留在被 Git 忽略的 `.local/`。

真实验收建议先戴耳机说：“用两句话推荐一个周末活动。”播报中说“嗯，继续”，再试“等一下，改成室内活动”；最后用外放重复，展开状态栏查看各段耗时，并记录误暂停、漏字与误提交。口音、背景人声、外放回声和长时间连续会话尚未由这次合成测试证明。
